# `paper/supplementary/`

Supplementary materials: appendices, extended data tables, code snippets, or
anything a reader would want to consult alongside the main paper but that does
not belong in the main flow.

## What goes here

- **Appendices** that are too long or too tangential for the main text. They
  can be included in the main PDF by appending
  `\input{supplementary/appendix_a}` to `paper/article.tex`, or kept as a
  separate file (e.g. `supplementary.pdf`) deposited alongside the main
  manuscript on Zenodo.
- **Extended data tables.** A long table that would break the typesetting of
  the main text belongs here as a separate CSV or PDF.
- **Code listings.** If the paper relies on a non-trivial script (a data
  analysis script, a small model), commit it here with a one-paragraph header
  explaining what it does. For larger code, link to an external repo instead.
- **Source datasets.** If the dataset is small enough to commit, place it
  here. If it is large, link to a Zenodo / Figshare / OSF deposit from the
  Data Availability statement in `paper/sections/08_backmatter.tex`.

## Conventions

- Each supplementary file gets a short README block (or a header comment for
  code) explaining what it contains and how it relates to the main text.
- Supplementary files are tracked in git (not ignored).
- If a supplementary file is regenerated by a script, commit both.
