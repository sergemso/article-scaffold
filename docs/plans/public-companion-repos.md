# Public companion repos for private article repos

Repo: `/home/ubuntu/projects/sergemso/article-scaffold` (a cookiecutter template; run Python from its venv: `make setup`, then `.venv/bin/python -m pytest <file>`; the whole suite takes about two minutes, so run single files while iterating). Scaffolded article repos are now private, but Zenodo's GitHub integration only archives public repos. This plan gives each article repo a public companion repo that receives an allowlisted snapshot on each final release, so Zenodo archives the companion.

Read first, in this repo: facts `docs/facts/0002-zenodo-github-integration-constraints.md` and `0003-repo-url-derived-in-metadata-code.md`; decisions `docs/decisions/0059-public-companion-repo-per-article.md`, `0060-companion-provisioning-and-auth.md`, `0061-companion-publish-trigger-and-gate.md`; guardrails `docs/guardrails/companion-*.md`; the procedure `docs/skills/enabling-zenodo-for-a-companion.md`. They hold the why; this file holds the what. Do not re-open the decisions; if one proves wrong, stop and mark the step `[!]` with the reason.

The design in one paragraph. Each article repo gets a root file `companion.yaml` (companion repo name, branch, allowlist, deny patterns), added to old repos by the existing `upgrade` command. `python3 -m scripts.article companion` builds a snapshot of allowlisted files plus the built PDF and DOCX, runs a leak scan and prints a JSON result. A new article-repo workflow `publish-companion.yml` runs on `v*` tags, builds with `reusable-build.yml`, and, only for a final `vX.Y.Z` equal to `metadata.yaml`'s version, commits the snapshot to the companion as `release vX.Y.Z`, tags it and creates a GitHub Release there (what Zenodo listens for). A new scaffold workflow `provision-companion.yml` (workflow_dispatch + workflow_call, idempotent, input `repo` or `all`) creates the public companion if absent and copies the scaffold's `COMPANION_PAT` into the article repo as secret `COMPANION_TOKEN`. `bootstrap-article.yml` calls it for new repos and now defaults to private. `metadata.py` makes `CITATION.cff` and the README citation point at the companion when `companion.yaml` exists.

Repo conventions that apply to every step: workflows under `.github/workflows/` and `{{cookiecutter.repo_name}}/.github/workflows/` are checked by `tests/test_ci_hardening.py` (actions pinned by major tag from its `MAJOR_TAGS` map, per-job `permissions`, a `concurrency` group, no `${{ }}` in `on:`); template workflows are copied without rendering (`cookiecutter.json` `_copy_without_render`); `{{cookiecutter.repo_name}}/` is the template tree; `tests/conftest.py` has `render`, `run`, `commit_all` and the `upgrade_template`/`upgrade_project` fixtures. Commit messages follow Conventional Commits with a `Refs:` trailer to the decision ids. Do not edit the generated block in `AGENTS.md`.
