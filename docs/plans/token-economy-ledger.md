Do: Create `{{cookiecutter.repo_name}}/scripts/article/ledger.py`.
- `key(kind, inputs, version, tier, tools)` hashes a canonical serialization (sorted names, length-prefixed values, a key-schema version) of file content with newlines normalized, never mtimes. A kind may declare a path as an input where the result depends on it. `tools` are declared statically (a string in the kind or check declaration), never obtained by running a tool.
- `get(root, kind, key)` and `put(root, kind, key, inputs, result)` store one file per key at `docs/ledger/<kind>/<key[:2]>/<key>.json`, written atomically (temp file plus rename). An entry holds the input name to hash map and the result, with no timestamp, so equal results are byte-identical and `put` of an equal result is a no-op. `put` of a different result for an existing key is refused and reported as a conflict. `error` and unavailable outcomes are never stored.

- A kind is registered with its declared input names in one table.
- CLI: `ledger get`, `ledger verify` (recompute keys from the stored input hashes and report mismatches), `ledger explain <kind> <key>` (which input hash differs from the nearest stored entry), `ledger evict <kind> <key> --reason ...` (the only delete; it writes a line to `docs/ledger/evictions.jsonl`), `ledger gc` (report entries whose inputs no longer exist; `--apply` removes them and logs them), `ledger stats` (hits, misses and conflicts counted per run, no content). There is no public `put`: entries are written only by `claims record` and `check record`. `ARTICLE_LEDGER=off` or `--no-ledger` bypasses lookups.

Resolved: `scripts/article/ledger.py`, the `ledger` CLI group, `schemas/ledger-result.schema.json`, `docs/ledger/README.md`, `.gitattributes` and `tests/test_ledger.py` are in. (7) `put` is an API only; the CLI has no verb that writes an entry, asserted by a test. (8) `docs/ledger/**` was already covered by the `docs/**` exclude; the default now names it and `paper/sources/**` explicitly.
