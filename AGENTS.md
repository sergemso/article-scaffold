# Agent execution plan — cold-start entry point

This repository is being hardened with an **agent-executable plan**. If you are
an AI coding agent and have no prior conversation history, read this file, run
the three commands below, and continue from the task card. Do not re-plan from
scratch and do not rely on chat context: the plan, progress, evidence, and
blockers are all on disk.

The human roadmap and review findings are in `docs/improvement-plan.md`. That
document is **background**, not the task queue. The canonical queue is
`plan/tasks.json`; progress is `plan/state.json`; history is
`plan/journal.md`.

---

## 1. Cold start (do this first)

```bash
python3 plan/agentctl.py doctor          # environment + plan health
python3 plan/agentctl.py status          # where we are
python3 plan/agentctl.py next --card     # the exact task to do now
```

If `doctor` reports `state.json missing`, run:

```bash
python3 plan/agentctl.py init
```

Then read only the files listed under `READ` in the task card. The card is
self-contained. If you need more context, use `rg` to find it; do not read the
whole repository or the whole improvement plan.

Once T02 is done, run `make setup` (or activate the venv it creates) before
tasks whose card says `pytest`; `agentctl` shells out to `python3`, so it must
see the same environment.

---

## 2. The only lifecycle you need

```bash
# 1. Claim (no-op if already yours; refuses a live lease held by someone else)
python3 plan/agentctl.py claim T05

# 2. Work in small steps. Checkpoint after each meaningful step.
python3 plan/agentctl.py checkpoint T05 --note "tojson applied to metadata.yaml"

# 3. Run the task's verification commands (records evidence + output tails)
python3 plan/agentctl.py verify T05

# 4. Only after verify passes: scope-check, commit, and close
python3 plan/agentctl.py done T05 --note "YAML/JSON parse under special chars"

# If stuck after two honest attempts:
python3 plan/agentctl.py block T05 --reason "needs decision: ..."

# If a previous agent died and the lease expired:
python3 plan/agentctl.py reclaim T05
```

`done` refuses to close a task when:

* the verify commands fail (unless `--skip-verify`, which is recorded and
  flagged by `audit`);
* changed paths fall outside the task's `touch` list (unless
  `--allow-outside-scope`, which is recorded).

A normal `done` creates **one task commit** plus a tiny
`chore(plan): record <id> @ <sha>` commit. Do not squash or rewrite them.

---

## 3. Rules that always apply

Full text, gates table and definition of done: `plan/PROTOCOL.md`.

1. In-progress tasks win: resume the active task, never start a parallel one.
2. Leases serialize writers; `reclaim` only for an expired lease or dead agent.
3. `state.json` is authoritative over your memory of the conversation.
4. Checkpoint before anything slow or risky (full tests, TeX build, bulk rename).
5. Never revert work you did not make; if unrelated changes exist, stop and ask.
6. Two attempts, then `block` with the failing command and the decision needed.
7. Do not edit completed tasks or rewrite history; plan changes are new tasks.
8. `touch` is a hard scope allowlist; commit as `task(<id>): <title>`.
9. Missing tools are not a pass: `verify` exits 3; skip only with a recorded note.
10. Read only the card's `READ` files; use `rg -n` instead of opening large files.
11. Decisions: `plan/decisions.md`; a product question is a `block`, then stop.
12. After the last task of a phase run `make test`, `agentctl audit`, and
    `agentctl render --write plan/STATUS.md`. Do not start optional tasks
    (P5, P6) without explicit human opt-in.
13. Done means: verify passes, only `touch` paths changed, `state.json` says
    `done` with a sha, and `journal.md` has the closing entry.

## Guardrails

Generated by `go-getter apply` from `docs/guardrails/`; do not edit this section.

Checked by git hooks and CI:

- The instruction file must stay within 150 lines (`instruction-file-within-cap`)
- Added lines must not contain secrets (`no-secrets-in-added-lines`)
- Host prompt logging must stay disabled (`prompt-logging-disabled`)
- Agents must not touch restricted paths and none may be committed (`restricted-paths-denied`)
- The .worktrees directory must be gitignored (`worktree-dir-is-gitignored`)

Blocked by host hooks where the host supports it:

- A gated action is preceded by a checkpoint (`checkpoint-before-gated-action`)
- Delegations to a role are routed by expected total step cost (`delegations-are-routed`)
- Irreversible commands need a human (`gated-actions-need-human-approval`)
- MCP calls carry no secret (`mcp-arguments-hold-no-secret`)
- Personal data is masked in tool output (`pii-masked-in-tool-output`)
- A step is not done while its verification checks fail (`verification-gate-blocks-done`)
- Watches start through go-getter watch, --until done for CI runs and long commands (`watches-use-the-wrapper`)

Advisory:

- No mid-task model, effort or instruction-file change; switches are confirmed (`cache-hygiene-rule`)
- Context is compacted at task boundaries (`compaction-timing-rule`)
- Handoffs must carry a brief, a result and evidence (`handoff-has-brief-result-evidence`)
- Agents hand over to a human only when blocked (`human-escalation-rule`)
- No more than 1 agents run at once (`max-concurrent-agents-rule`)
- Noisy work is delegated only when the cost model says the handoff is cheaper (`noisy-work-rule`)
- Parallel tasks must each use their own worktree (`parallel-tasks-use-worktrees`)
- Detailed procedures live in skills loaded on demand (`procedure-delivery-rule`)
- Restricted data is handled only on hosts with a blocking pre-tool hook (`restricted-data-hosts-rule`)
- The reviewer must not modify files (`reviewer-read-only`)
